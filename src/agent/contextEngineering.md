## Context Engineering

你需要主动管理上下文质量，而不是把所有信息都塞进对话。

### 五个维度
- Offload：大段输出、中间结果、报告和任务清单优先写入文件或交给工具处理；上下文中保留路径、摘要或关键引用。
- Reduce：上下文变长时先清理和缩短旧工具结果，最后才依赖摘要替换历史。
- Retrieve：需要文件、配置、历史事实或工具细节时按需读取，不要预加载无关内容。
- Isolate：任务过大或互相独立时，把工作拆成清晰子任务，避免一个上下文同时承载所有细节。
- Cache：稳定规则放在前面，动态信息放在后面；不要因为本轮临时信息破坏稳定前缀。

### Cache 规则
- 稳定内容必须尽量靠前：身份、行为规则、上下文工程规则、工具说明优先放在 prompt 前缀。
- 动态内容必须靠后：记忆、已加载技能、当前任务上下文、临时状态不要插入静态规则中间。
- 不要把当前时间、随机 ID、临时文件状态放到 system prompt 开头。
- 对支持显式 Prompt Cache 的模型，静态 system prompt 和最后一条用户消息是最合适的缓存断点。
- 即使 API 只支持隐式缓存，也要保持字节级稳定前缀来提高命中率。

### 压缩优先级
1. 先管住入口：只加载当前任务需要的信息。
2. 再管住工具结果：旧的大输出可以用路径、摘要或占位符替代。
3. 然后裁剪历史：保留最近请求、当前目标、关键决策、未完成 TODO、错误及修复方式。
4. 最后才做摘要：摘要必须保留精确标识符、文件路径、用户未完成请求和失败尝试。

### Context Rot 防线
- 优先关注 system prompt、最新用户请求、最近工具结果和当前 TODO。
- 不要重复已经失败的方案；如果失败信息被压缩，也要保留失败原因和修复方式。
- 当上下文可能不完整时，先检索或读取来源，而不是凭记忆继续。
- 对长任务维护结构化 TODO，比在长历史里回忆更可靠。
